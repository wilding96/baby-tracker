# POP3D M5 批次 3a-FX（弹幕表现力补丁）Implementation Plan

日期：2026-10-09　前置：批次 3a（弹型/僚机/环绕弹）已验收

**触发**：试玩反馈"太扁平了，子弹很无聊"。诊断（有数可算）：720p 画布下场地
≈10.6 像素/世界单位，我方弹体只有 2.6~13px（敌机是 ~32px），且是 `MeshBasicMaterial`
纯平涂、无描边、无拖尾，未拿元素卡时还全是同一种青色。

**范围**：只动表现层，不改玩法数值（除了把弹体判定半径同步放宽 1.2 倍，避免"看着打中却没伤害"）。

## 实现清单

| # | 项 | 落点 |
| --- | --- | --- |
| 1 | 弹体放大 1.5 倍 + ink 描边壳 | `BULLET_VIS.scale/outline`、`render/assets.ts` |
| 2 | 加法混合的外圈辉光贴片（环形渐变，1 个 draw call） | `createGlowTexture/Geometry`、`scene.ts` |
| 3 | 拖尾：位置由速度反推（不存历史、零分配），3 节/发 | `BULLET_VIS.trail/trailGap/trailDim`、`scene.ts` |
| 4 | 属性差异：电＝锯齿残影 / 火＝拖焰 / 冰＝旋转菱形 | `scene.ts` 拖尾分支 |
| 5 | 僚机独立枪口闪光 | `Wingman.muzzle`、`game.ts`、`scene.ts` |
| 6 | 命中火花（复用爆点池，节流 ~33/秒） | `FX.hitSpark`、`game.ts#spawnSpark` |
| 7 | 背景速度线（26 条，1 个 draw call） | `FX.speedLines`、`scene.ts` |
| 8 | Bloom 后处理：桌面开、移动端关，`?bloom=0/1` 可覆盖 | `FX.bloom*`、`scene.ts` composer |
| 9 | **逐层开关** `?fx=…`：定位"哪一层让画面变线框/变糊" | `RendererOptions.fx`、`page.tsx` |

**Bloom 的关键取舍**：阈值取 `1.0`（线性亮度）。米色场地线性亮度 ≈0.94 不参与发光，
只有加法辉光贴片叠出来的"过曝"区域会发光——于是背景不糊、弹芯保持纯色。
`EffectComposer` 默认用 HalfFloat 渲染目标，加法叠加可以越过 1.0，这是这套做法的前提。

## 验收读数

`?stress=1` + 新星机型，点「开始」等 10 秒，连读 3 次：

| 配置 | FPS | 帧耗时 | 同屏弹幕 | draw call |
| --- | --- | --- | --- | --- |
| 批次 3a（改动前） | 60 | 16.7 ms | 544~552 | 15~16 |
| 3a-FX，`?bloom=0` | 60 | 16.7 ms | 546~552 | 19~20 |
| 3a-FX，默认（bloom 开） | 60 | 16.7 ms | 548~552 | **33** |
| 3a-FX，`?fx=0`（全关基线） | 60 | 16.7 ms | 549 | 17 |
| 3a-FX，`?fx=bloom`（只开后处理） | 60 | 16.7 ms | 548 | 29 |

- 新增表现层固定成本 +4 draw call（描边 1 + 辉光 1 + 拖尾 1 + 速度线 1）；
  bloom 追加 ~13（5 级模糊 × 双向 + 亮度提取 + 合成）。
- 33 < §4.3 的 60 红线；移动端 `(pointer: coarse)` 直接关 bloom，回到 ~20。
- 普通局（`?auto=1`，新星）同样 60fps / 16.7ms / DC 32~34，console 零报错。

## 调参入口（不用碰渲染代码）

- `BULLET_VIS`：`scale` / `outline` / `glow` / `glowGain` / `trail` / `trailGap` / `trailDim`
- `FX`：`bloom` / `bloomStrength` / `bloomRadius` / `bloomThreshold` / `speedLines` / `hitSpark`
- 运行时 A/B：`?bloom=0`（关 bloom）、`?bloom=1`（强制开，含移动端）
- 逐层二分：`?fx=0` 全关；`?fx=outline,glow,trail,lines,bloom` 任意组合

## 首轮反馈后的收紧（2026-10-09）

第二轮反馈（"射速太高 / 拖尾太重 / 打击感不强 / 本体战机不要闪 / 动态留给重要内容"）
之后的动作：

- **本体战机不再闪烁**：无敌期的 24Hz 交替隐藏改为**恒亮护盾环**（3/4 圆弧、慢转）；
  去掉玩家机与僚机"每发缩放脉冲"（高频射击下等于持续闪）。
- **常规射击不再拖尾**：改为 `BULLET_VIS.trailByKind`，默认只有**追踪弹**给尾焰。
- **视觉调试模式**：默认隐藏属性流卡（`?cards=all` 恢复），免得弹色被属性卡随机改掉。
- **按机型上色**（只影响渲染，不动克制计算）：离子=青、新星=红、脉冲=蓝。
- **追踪弹**：拉长的八面体（小飞弹）+ 3 节尾焰；**僚机**：后掠翼 + 稳态翼尖灯 +
  随横向位移的轻微侧倾（一架僚机从 4 个 draw call 降到 3 个）。

> 待办：draw call 预算趋紧。实测 2 颗环绕弹 + bloom = DC 37；满配
> （4 架僚机 + 4 颗环绕弹）估算 ~53，仍在 60 红线内但没有余量，
> 后续加"激光"时要盯住这条线（激光计划用 ≤3 个 mesh）。

### 第三轮：初始单发 + 2/3 号机辨识度（2026-10-09）

三把枪的**初始形态都是每发 1 枚**，多弹交给卡（扇形弹）与主武器等级；
差别放在"单发多重 / 射速多快 / 弹形多粗"。三者 DPS 都落在 ~210/秒：

| | 离子炮 | 新星 | 脉冲 |
| --- | --- | --- | --- |
| 弹数（初始） | 1 | 1 | 1 |
| 单发伤害 | 32.5 | 40 | 32 |
| 实际冷却 | 0.15s | 0.19s | 0.16s |
| 弹速 | 62 | 44（重、慢） | 34（慢，大） |
| 弹形 | 细长条 | **粗短子弹头**（1.0×1.35 菱形） | **多面体火球**（半径 0.62，自转） |
| 散射倍率 | 0.6（集中） | 1.6（霰弹铺开） | 1.0 |
| 特殊 | 贯穿 1 | — | **左右摇曳**（amp 0.95 / 7.5 rad·s⁻¹） |
| 菜单文案 | 贯穿单发 · 高单体 | 重炮单发 · 一击见效 | 摇曳火球 · 大判定 |

脉冲第三版按"魂斗罗 F 弹"重做，第四版定稿为**长哑铃**：

- 造型：两瓣小球（半径 0.38）+ 中间一根细连杆（粗 0.21），整体长 2.86 世界单位 ≈30px，
  小球直径只有 8px —— 长度 : 球径 ≈ 3.8:1，是"哑铃"不是"两个大球"。
- 判定：**连杆也算判定**（把敌机投影到杆上取最近点，即胶囊判定）。
  所以"看着连上了就是真连上了"；打空来自它自己的**随机弹道**。
- 随机性（每发不同）：初始相位、自转方向/速度（7 rad/s 量级）、恒定横漂 ±1.1、
  蛇形 amp 0.9 / freq 3.6 各带 0.4~1.5 倍抖动。
- 无头取证：14 发火球的最大横向偏离 0.07~1.96，其中超过"正前方命中条件"
  （|偏离| ≤ 1.88 = 无人机 1.5 + 弹瓣 0.38）的约 1/7 —— 也就是**直线也会打空**。

> 踩坑记录：`IcosahedronGeometry` 是**非索引**几何、`BoxGeometry` 是索引几何，
> `mergeGeometries` 混用会**返回 null**，然后在 `WebGLRenderer.render` 里炸
> `reading 'id' of null`。连杆必须先 `toNonIndexed()`；并且加了兜底（失败就退回一颗球）。

### S2：1 号机 = 逗猫棒激光笔（常驻光束）

主题定稿：三把枪 = 宠物道具 —— **✨激光笔 / 🐟小鱼干 / 🦴骨头**（机身按钮的
`电/火/冰属性` 标签在视觉调试期一并藏掉，`?cards=all` 才显示）。

| 项 | 设计 |
| --- | --- |
| 形态 | 机头 → **落点**的一道常驻光束：绿本体（不透明 `PAL.laser`）+ 绿外晕 + 落点光斑 |
| 判定 | 以 `world.beam` 为唯一真相：竖线（x = 玩家 x，z ∈ [z1,z0]）± `halfW`，渲染读同一组数 |
| 伤害 | 连续 DPS = `单发伤害 ÷ fireCd`，于是**超频卡 = DPS 提升**；元素/灼烧/减速/连锁照常吃 |
| 升级 | 只加宽：`halfW = 0.5 + (弹数成长) × 0.2`（实测拿 1 层扇形弹 0.50 → **0.70**） |
| 卡牌兼容 | 分裂弹 → 命中处的末端溅射环；**贯穿卡每层多穿一个目标**（默认只打最靠前的一个）；追踪弹/僚机/环绕弹不受影响 |
| 成本 | 3 个 mesh（外晕 / 白芯 / 落点），不生成子弹 |

无头取证（`stress` 免死跑 16 秒）：光束 active、半宽 0.50→0.70、**我方子弹数恒为 0**、
击杀 18 / 得分 180，切到骨头机型后 `beam.active = false`。实机 60fps / 16.7ms / DC 33 / console 零报错。

> 首轮试玩反馈修的两点：
> 1. **"看着是白的"** —— 原来芯是白色加法混合，把绿晕整个盖住了。改成
>    **不透明绿本体 + 绿外晕**（去掉白芯），颜色才真的是绿的。
> 2. **"遇到敌机直接穿过去"** —— 原来光束固定画到场地顶端、只是把光斑挪到敌人身上。
>    现在**光束长度画到落点为止**（`tipZ`），默认只结算最靠前的一个目标，
>    贯穿卡每层才多穿一个：视觉与判定同源，打到谁就停在谁身上。

配色也随之修正：离子=青、新星=**深蓝**、脉冲=**橙**。原因是我之前把新星设成红色，
而 §5 可读性约定里**红留给敌弹、品红留给敌机**——玩家弹不能用它们。
实测同屏我方弹（`?auto=1`，开局 6 秒）：离子 6 / 新星 7 / 脉冲 8，60fps、console 零报错。

试玩反馈"像渲染引擎未经渲染的线框图"，据此先把三层最可疑的参数调保守：

| 参数 | 初值 | 现值 |
| --- | --- | --- |
| `BULLET_VIS.trail` | 3 | 2 |
| `BULLET_VIS.trailDim` | 0.55 | 0.42 |
| `BULLET_VIS.glow` / `glowGain` | 1.6 / 1.2 | 1.3 / 0.7 |
| `FX.bloomStrength` / `bloomRadius` | 0.9 / 0.5 | 0.6 / 0.35 |
| 速度线 条数/长度/不透明度 | 26 / 16 / 0.16 | 14 / 7 / 0.10 |

下一步待人工二分：用 `?fx=…` 单层开关确认"线框感"来自哪一层
（速度线 → 拖尾 → 描边 → 辉光 → bloom），或者 `?fx=0` 仍然线框 = **底子问题**
（场地网格 + 满屏 ink 描边 + 平涂材质），那就要改基础美术而不是特效。

## 未验证 / 风险

- **画面本身没有人眼确认**：实现环境读不了截图，配色与"够不够炫"需要人工过目；
  参数已集中到 `BULLET_VIS` / `FX`，不满意直接调数字。
- **移动端未实测**：只按 `(pointer: coarse)` 关 bloom，未在真机验证 60fps。
- bloom 阈值与"米色场地不发光"的边界只差 0.06（0.94 vs 1.0）；若背景色以后调亮，
  需要同步抬高阈值或压暗场地。
- 拖尾是加法混合、且排在透明队列（在所有不透明物体之后绘制），会轻微提亮它扫过的敌机；
  如果实测觉得伤可读性，把 `BULLET_VIS.trail` 降到 1~2。
