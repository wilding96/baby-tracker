# 波普风雷电 Roguelite 改造 —— 设计纲要 v1

日期：2026-10-08
对象：`src/app/game/raiden/`（现有竖版雷电 Like Roguelite STG）
目标：让它不再"无聊"，同时满足"稳定流畅"的硬指标。

本文件是两条并行赛道的共用任务书。任何实现都必须服从下面的第一节和第三节。

---

## 一、美术方向：纯波普（已拍板）

风格坐标系：**利希滕斯坦式波普**——硬边几何线、Ben-Day 网点、印刷原色。
明确不要：《茶杯头》那种橡皮管弧线、水彩、做旧质感；也不要现代霓虹辉光。

### 1.1 渲染硬约束

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| R1 | 前景纯色 | 玩家机、敌机、**所有子弹**一律实色填充 + 黑色粗描边，禁止网点、渐变、模糊 |
| R2 | 网点只进背景层 | Ben-Day 网点只允许出现在背景、UI 底板、Boss 血条底、爆炸余韵层 |
| R3 | 零模糊 | 全面禁用 `shadowBlur` / 辉光 / 体积光 / 半透明烟雾 |
| R4 | 层级对比 | 背景对比度必须显著低于前景，保证 0.1 秒内看清"我在哪、危险在哪、奖励在哪" |
| R5 | 硬边锐利 | 必须做设备像素比（DPR）适配，波普的线条一虚就废 |

### 1.2 调色板

```
POP_RED      #FF2D2D   敌弹 / 危险
POP_MAGENTA  #E5007E   Boss 弹 / 强调
POP_YELLOW   #FFD400   奖励 / 高分
POP_BLUE     #0057FF   玩家子弹
POP_CYAN     #00C2FF   玩家机体 / 护盾
INK          #101010   所有描边、字体
PAPER        #FFF8E7   纸白 / 底板
```

### 1.3 语义色（沿用"同色即同义"，不得混用）

```
玩家子弹 = POP_BLUE
激光     = PAPER（INK 描边）
敌弹     = POP_RED
Boss 弹  = POP_MAGENTA
奖励     = POP_YELLOW
护盾     = POP_CYAN
预警     = POP_RED + 网点闪烁
```

### 1.4 打击反馈：拟声词

波普从漫画继承的语汇，别的风格用会怪，本风格用是本色。

- 小怪爆炸 → `POW!`
- 精英 / Boss 阶段击破 → `BOOM!`
- 满屏清怪 → `KAPOW!`（屏幕中央，粗体描边）

全部为硬边粗体 + INK 描边，禁止发光。

## 二、机制清单（已拍板）

### P0 —— 直接治"无聊"，必做

1. **流派卡**：局内三选一从"数值卡"改为"行为卡"。卡要能改变开火或触发方式
   （例：命中分裂、击杀回血、子弹反弹、连锁闪电、穿透、环绕护卫），
   至少 12 张，能明确归入 3~4 个流派，不存在"冷板凳"。
2. **每局 1 次原地复活**：血归零不直接结束，给一次重返战场的机会。
3. **属性克制**：精英与 Boss 带抗性/弱点，逼玩家临场调整 build。

### P1 —— 明显加分

4. **局外养成**：用每局战果解锁永久属性或装备，给"再来一局"一个理由。

### 暂不做

- 萌宠驾驶员（成本高，留到后面）

---

## 三、性能硬指标（不可让步）

1. 中端手机全程稳定 60fps，弹幕峰值 **400+ 子弹**不掉帧
2. 游戏循环内 **零 React 重渲染**
3. 单帧的 canvas 状态切换（`save/restore`、`fillStyle` 变更、路径重建）显著下降
4. 所有高频实体走对象池，循环内不产生新对象
5. 设备像素比适配，硬边不糊

## 四、两条并行赛道

### Track A —— 方案 2「先拆后加」的第一步：地基

在现有 `src/app/game/raiden/` 上就地改造，只做**结构 + 性能 + 波普视觉**，
本轮**不新增机制**（流派卡、复活、克制、养成留到地基打好之后的下一轮）。

交付：游戏仍然完整可玩，但循环内不再触发 React 重渲染、全面去模糊、
支持 DPR、精灵离屏预渲染，整体视觉切到波普。

### Track B —— 方案 3「引擎级重写」的最小 demo

全新独立文件，零依赖零构建，只证明两件事：

1. 波普视觉在竖版弹幕里能有多好看
2. 这套新引擎的性能天花板在哪（400+ 子弹是否真能稳 60fps）

交付一个可玩的单文件 demo，带实时 FPS / 子弹数显示。

### 决策方式

两条赛道跑完后对照 demo 决定走哪条。Track B 若明显胜出，
则以它为新地基，把 Track A 验证过的性能手法搬过去。
