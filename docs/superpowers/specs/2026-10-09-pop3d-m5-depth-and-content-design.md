## 0. 背景

M0–M4 已完成并验收（骨架 / 手感 / 节奏 / 复玩 / 打磨），但试玩反馈集中在两点：

1. **内容太薄**：我方子弹只有一种弹型；僚机只是一对固定偏移的子弹、没有实体；敌机几乎不开火；敌弹只有一种自机狙；Boss 只有"摇摆 + 扇形 + 螺旋"三件套。
2. **看着平**：用了 three.js 但画面像 2D。

M5 解决这两点。

## 1. 红线（不可让步，沿用 §4/§5/§9）

1. 弹幕可读性 > 立体感。**任何情况下玩家机、敌弹、奖励必须一眼分清**。
2. 中端设备 60fps；同屏 400+ 弹幕不掉帧；每帧 draw call < 60。
3. 游戏循环内零分配（高频实体一律池化）。
4. `engine/` 不出现 React；`page.tsx` 不出现逐帧状态。
5. 不用 `shadowBlur` / 辉光 / 全屏模糊 / 后处理。

## 2. 立体感（方案 C：弱透视 + 纵深线索 + Boss 运镜）

### 2.1 相机：正交 → 长焦弱透视

| 项 | 现在 | M5 |
| --- | --- | --- |
| 相机 | `OrthographicCamera` | `PerspectiveCamera` |
| 俯角 `pitchDeg` | 16° | 32° |
| fov | — | 15°（长焦，压远近比） |
| 距离 | 固定 120 | **按取景高度反推**：`d = halfViewH / tan(fov/2)` |
| 取景逻辑 | `halfViewH = max(halfH×marginY, halfW×1.06/aspect)` | 不变 |

**为什么用长焦而不是普通透视**：场地从下沿到上沿有约 ±27 单位深度差。相机一近，远端会缩到近端的三分之一，弹幕"上小下大"无法判读。fov 15° 时远近尺寸比约 **1.25 : 1**——有纵深，不伤判读。

保留 `CAMERA.mode: "ortho" | "persp"` 开关（默认 `persp`），用于一键出对照截图。

> `pointerToWorld` 用射线与地面求交，正交/透视都成立，不需要改。

### 2.2 高度分层

| 层 | Y | 说明 |
| --- | --- | --- |
| 地面 / 网格 | 0 | |
| 场地边框 | 0.02 | |
| **贴地投影** | 0.04 | 每个实体的"真实位置"标记 |
| 爆点 | 0.5 | |
| 玩家 / 僚机 | 0.8 | |
| 我方子弹 | 1.0 | |
| 敌机 | 1.3 | |
| 敌弹 | 1.5 | 最高，永远压在最上层 |
| 拟声词 | 3.0 起，向上飘 | |

### 2.3 位置补偿（保证"看到的 = 判定点"）

透视 + 俯角会让高处物体在屏幕上产生上移。若直接按 `(x, h, z)` 绘制，敌弹会画在比判定点高约 10px 处，产生"明明躲开了却中弹"。

**做法**：绘制位置加偏移

```
renderZ = z + h * tan(pitch)
```

实体因此落在**与地面判定点完全相同的像素**上。纵深感改由三样承担：

1. 透视下的远近尺寸差（1.25:1）
2. 遮挡顺序
3. 实体与其**贴地投影**之间的"离地"间距

### 2.4 贴地投影

- 一个 `InstancedMesh`（压扁圆片，`CircleGeometry` 绕 X 轴 -90°），容量 64，颜色 ink，`opacity 0.18`。
- **不用加法混合**：底色是纸白，加法会洗白。
- 覆盖：玩家 1 + 僚机 4 + 敌机 48 + Boss 1 + 余量。
- 半径 = 实体半径 × 1.6。
- 收益：实体"离地"；投影同时给出真实位置，与 2.3 的补偿互为印证。

### 2.5 光照

- 保留环境光 1.05 + 主方向光 1.7（左上后方）。
- 新增一盏 0.35 强度的反向补光，避免低多边形背面死黑。
- **不开 shadow map**：用 2.4 的贴地投影替代，更便宜也更贴波普硬边风格。
- 继续 flat shading（立体感主要来源，不能砍）。

### 2.6 背景（全部 opacity ≤ 0.15）

- 远层网格：边长 128、格 4，opacity 0.05，滚动 ×0.6
- 近层网格：边长 64、格 2，opacity 0.10，滚动 ×1（现有）
- 5 条纵向长线（x = ±12, ±6, 0），z ∈ [-40, 40]，opacity 0.06，随近层滚动
- 背景对比度永远低于前景

### 2.7 Boss 运镜（只在无弹幕的过场窗口偏离俯视）

相机 rig 维护 `{ pitch, distMul }` 目标值，按约 3/s 插值。

| 事件 | 时长 | 运镜 | 安全性依据 |
| --- | --- | --- | --- |
| `bossIntro` | 2.0s | pitch 55° → 32°，distMul 1.3 → 1.0 | 入场阶段本就无弹幕、不可被击中 |
| `bossPhase` | 0.6s | distMul → 0.85 后回位，同时**清空敌弹**＋停帧 0.14s | 清屏后场上无弹幕 |
| `bossDown` | 1.5s | distMul → 1.35，`timeScale 0.25` 慢动作 | 敌人已全灭 |

常规战斗**永不偏离俯视**。这是 C 方案不踩红线的关键。

## 3. 我方子弹多样化

### 3.1 弹型表

| `BulletKind` | 几何 | 速度 | 伤害 | 行为 |
| --- | --- | --- | --- | --- |
| `bolt` 离子束 | Box 0.25×0.25×2.6 | 62 | ×1.25 | 天生贯穿 +1 |
| `spread` 散射弹 | Octahedron 0.36 | 46 | ×0.80 | 基础扩散角 0.09 |
| `wave` 冲击波 | RingGeometry（平躺） | 40 | ×1.00 | 命中后向两侧溅射 2 发 `mini` |
| `homing` 追踪弹 | Octahedron 0.30 | 34 → 52 | ×0.70 | 比例导引，最大转向 2.6 rad/s |
| `mini` 子母弹 | Octahedron 0.18 | 38 | ×0.35 | 由 `split` / `wave` 产生 |
| `orbit` 环绕弹 | RingGeometry（小） | — | ×0.90 | 绕玩家公转，接触伤害 |

- 机型默认弹型：`ion → bolt`、`nova → spread`、`pulse → wave`
- 属性叠加表现为**颜色 + 拖尾**：电＝锯齿残影、火＝弹头拖焰、冰＝旋转菱形
- `homing` 用比例导引，并把角度差归一化到 -π~π（避免绕远路）

### 3.2 渲染与池

- 仍是**一个对象池 + `kind` 字段**；渲染时按 kind 分发到各自 `InstancedMesh` 的写入序号（保持零分配）
- 弹型 ≤ 6 → 最多 +6 draw call

### 3.3 卡驱动

- `split` 分裂弹：主弹命中后分裂成 2 发 `mini`（Lv2 → 4 发）
- `homing` 追踪弹：每次齐射附带 N 发追踪弹（N = 卡层数）
- `orbit` 环绕护卫弹：Lv1 给 2 发、Lv2 给 4 发环绕弹

## 4. 僚机实体化

现在 `wing` 卡只是"从固定横偏移多射两发子弹"，没有实体。改为：

- **实体池** `wingmen`（上限 4）：位置、弹簧速度、独立开火冷却、存活标记
- **跟随**：目标点在玩家两侧后方（±2.6, +1.2），弹簧滞后跟随（k ≈ 10/s）
- **射击**：独立冷却 = 主武器冷却 × 1.15；弹型**继承主武器弹型**；伤害 ×0.6；继承**属性**与**贯穿**加成
- **弹数固定为每架每次 1 发**：`扇形弹` 只给主炮加弹数，不给僚机加（否则 4 架 × 多发会让弹幕数量爆炸，也失去"主炮 / 僚机"的分工）
- **视觉**：玩家机几何缩到 0.55，青色 → 蓝色，带描边；有独立枪口闪光与贴地投影
- **不做碰撞判定**（不被撞毁），控制复杂度

### 卡片改造

| 卡 | 现在 | M5 |
| --- | --- | --- |
| `wing` 侧翼僚机 | Lv1 两侧各加一门固定副炮；Lv2 再加一对 | **Lv1 ＝ 2 架 / Lv2 ＝ 4 架实体僚机** |
| `wingrate` 僚机超频（新） | — | 僚机射速 +25%（max 2） |
| `winglink` 僚机协同（新） | — | 僚机命中给主武器叠 1 层增伤（每层 +4%，上限 5 层，2s 衰减）（max 2） |

## 5. 敌机弹幕

### 5.1 先让敌机真的开火

| 敌种 | 现在 | M5 |
| --- | --- | --- |
| `drone` | fireCd 2.6s，单发自机狙 | fireCd **1.6s**，`ball` 单发 / 三连点射 |
| `gunner` | fireCd 3.0s，单发 | fireCd **2.0s**，`diamond` 三向散射 + 偶发 `ring` |
| `weaver` | 不开火 | 每当正弦摆动到达极值（端点）时打一发 `long` |
| `turret`（新） | — | 随波次进场，**在场地中段停留 12s 后离场**；`laser` 预警激光 + 环形爆发 |

补充：

- 敌机入场 1s 后立即进入射击节奏（不再有长空窗）
- 每次开火前 0.25s 有枪口预警闪光（可读性）
- **目标密度**：常规波次同屏敌弹从"个位数"提到 **60~150**

### 5.2 敌弹弹型（6 种）

| `kind` | 几何 | 用途 |
| --- | --- | --- |
| `ball` 圆弹 | Sphere | 自机狙，基础 |
| `diamond` 菱形弹 | Octahedron | 散射 |
| `long` 长条弹 | Box（细长） | 高速直射 |
| `ring` 环弹 | Torus（细） | 环形爆发 |

## 6. Boss 战重做

### 6.1 结构

- **三阶段**，HP 阈值 66% / 33%
- **可破坏部位**：两门副炮（各 500 HP）。打掉后 P1 弹幕墙出现宽缺口 → "打哪里"第一次有意义
- **弱点每阶段刷新**（electric / fire / ice 轮换），逼玩家用属性卡应对

### 6.2 时间轴驱动

每阶段是一条事件表，引擎每帧比对 `bossPhaseTime` 是否越过事件时间：

```ts
interface BossEvent { t: number; action: () => void }
```

| 阶段 | 行为 |
| --- | --- |
| P1 弹幕墙 | 两门副炮轮流射出**带缺口**的弹幕墙，缺口位置逐轮移动；副炮被打掉后缺口变宽 |
| P2 旋转 + 自机狙 | 核心双臂螺旋喷射；每 2s 一次三点自机狙；召唤 2 架 `drone` |
| P3 狂暴 | 环形爆发 + 激光扫射（带预警）+ 移速加快 + 召唤频率翻倍 |

### 6.3 演出

- 入场运镜（见 2.7）+ 现有 BOSS 警告横幅 + 全屏闪
- 阶段切换：停帧 0.14s + 强震 + 核心爆闪 + **清空敌弹**（喘息窗口）
- 击破：慢动作 1.5s（`timeScale 0.25`）+ 8 段延迟连锁爆炸 + KAPOW + 星尘掉落
- 血条分 3 段显示，当前段高亮

### 6.4 时长目标

- 单场 Boss 战目标 **45~75 秒**（现在约 35 秒）；清屏喘息会天然拉长节奏
- HP 缩放保留（`BOSS.hp × (1 + hpPerLevel × 选卡数)`），数值待实测后定
- 整局目标维持 **3~4 分钟**

## 7. 卡牌系统：修正与扩展

### 7.1 修 bug（必须先修）

`rollOffer` 现在写成：

```ts
const fresh = CARDS.filter((c) => (cards[c.id] ?? 0) < c.max);
const src = fresh.length >= n ? fresh : CARDS;   // ← 不足 3 张时退化到全池
```

于是可能发出**已满层**的卡；`chooseCard` 遇到满层会直接 `return`，玩家点了没反应（三选一被卡住）。

**改为**：只从未满层的卡里抽；不足 3 张就**少发几张**（乃至一次发 1 张），绝不发满层卡。

### 7.2 选取算法：加权 + 协同 + 互斥 + 保底

```
weight = base            // 1.0
       × (1 + 0.35 × 已有标签命中数)
       × 稀缺系数         // common 1.0 / rare 0.45
       × 保底系数         // 该稀有度连续未出时每次 +0.15，上限 2.0
```

- 每张卡带 `tags`（`fire` / `spread` / `laser` / `wing` / `element` / `econ` …）
- `excludes`：互斥卡不同时出现
- `requires(cards)`：前置卡（如 `wingrate` 需 `wing ≥ 1`）

### 7.3 卡池 16 → 24 张

| id | 流派 | 前置 | 效果 |
| --- | --- | --- | --- |
| `wingrate` | 弹幕 | wing ≥1 | 僚机射速 +25% |
| `winglink` | 弹幕 | wing ≥1 | 僚机命中给主武器叠增伤 |
| `homing` | 弹幕 | — | 每次齐射附带 N 发追踪弹（N = 卡层数） |
| `orbit` | 弹幕 | — | 环绕护卫弹 |
| `split` | 弹幕 | — | 主弹命中分裂 |
| `overcharge` | 元素 | rate ≥2 | 属性伤害 +30%，射速 -10% |
| `shield` | 生存 | — | 每 20s 获得一次抵挡 1 次伤害的护盾 |
| `luck` | 经济 | — | 三选一多出一张候选 |

### 7.4 三选一 UI

- 卡片错峰入场动画（0.06s 间隔）
- 卡面显示"当前 Lv / 上限"
- 抽卡与选卡音效沿用现有 `gachaCard` / `buttonClick`

## 8. 采纳的工程建议（来自外部评审）

1. **触摸改相对拖动**：现在手指点哪飞机飞哪，手机上飞机永远压在手指下、看不见自己。改为记录按下点 + 位移量驱动（灵敏度 1.2）。**这项进批次 1**
2. **种子随机 `mulberry32`**：现在全用 `Math.random()`，无法复现。改为引擎持有种子 RNG，`?seed=` 可复现、可做每日挑战
3. **升级池加权**（并入 §7.2）
4. **Boss 时间轴数据驱动**（并入 §6.2）
5. **弹幕/波次/升级外置成数据模块**：`engine/patterns.ts`、`engine/waves.ts`、`engine/upgrades.ts`，替代 `game.ts` 里写死的生成逻辑
6. **移动端渲染开关**：移动端关闭 `antialias`、显式声明 `alpha:false / stencil:false`、DPR 上限 2 → 1.5

## 9. 明确不做（附理由）

| 项 | 理由 |
| --- | --- |
| 空间哈希 | 现在最坏 400 我弹 × 48 敌机 ≈ 1.9 万次距离比较/步，实测 546 弹幕 60fps；等敌机上百再上 |
| 连续碰撞（线段-圆） | 物理固定 1/60 步进、掉帧丢时间，单步最大位移 0.87 单位 < 最小碰撞半径和 1.73，结构上不会穿 |
| SoA TypedArray 替对象池 | 这个量级收益可忽略，可读性代价大 |
| `THREE.Points` 画子弹 | M5 要做多种弹型，Points 只能全同形 |
| 加法混合（AdditiveBlending） | 底色是纸白，加法会把弹幕洗成白块 |
| 去掉光照改全 MeshBasicMaterial | 低多边形平涂的立体感就来自方向光斜面明暗，砍掉反而更平 |
| Rogue DAG 推图 | 那是另一种游戏结构（多节点推图），我们是"单局 3 分钟 + 局内三选一"，YAGNI |
| shadow map | 用贴地投影替代，更便宜也更贴波普硬边风格 |

## 10. 交付顺序

1. **P0 · 卡牌 bug 修复**（§7.1）——独立小改动，先落地
2. **批次 1 · 观感**：§2 全部（弱透视 + 高度分层 + 位置补偿 + 贴地投影 + 光照 + 背景 + Boss 运镜骨架）、§8.1 触摸相对拖动、§8.6 移动端渲染开关
3. **批次 2 · 数据模块化**（§8.5，纯重构、行为不变）：`engine/patterns.ts` / `waves.ts` / `upgrades.ts`
4. **批次 3 · 内容**：§3 弹型、§4 僚机、§5 敌弹、§6 Boss、§7 卡牌扩展
5. **批次 4 · 收口**：§8.2 种子随机、平衡复测

两条顺序理由：

- **先看观感、再堆内容**：立体感一动，后面所有弹幕的可读性都要在**新相机**下重新校一遍，顺序反了会返工。
- **数据模块化必须排在内容之前**：批次 3 要加 6 种弹型 × 4 敌种 × 3 阶段 Boss × 24 张卡，继续写在 `game.ts` 里会失控；先抽成数据模块，内容才是"填表"而不是"改逻辑"。

## 12. 风险

1. **透视下的判读**：2.3 的位置补偿是关键防线；若补偿公式落地后仍出现"看到的位置 ≠ 判定点"，回退到 `mode: "ortho"` 并保留其余纵深线索。
2. **内容量**：批次 2 涉及 6 种弹型 + 4 敌种 + 3 阶段 Boss + 24 张卡，是 M5 的主要工作量，可能需要再拆。
3. **平衡**：僚机、新弹型、Boss 三阶段都会抬升 / 压低难度曲线，需要重新实测；能用 `?auto=1` 自动驾驶员跑通整局作为回归手段。
