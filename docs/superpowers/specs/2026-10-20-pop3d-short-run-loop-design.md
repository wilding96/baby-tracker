# POP3D 短局循环设计

日期：2026-10-20
对象：`src/app/game/pop3d/`
前置：`docs/superpowers/specs/2026-10-10-shmup-final-direction.md`

---

## 0. 结论

把 pop3d 从"一次性的 4 分钟演示"改成**单局约 100 秒、抽卡 3 次、通关后难度晋升**的循环。

三件事一起改，缺一件都不成立：

1. **压缩单局**：Boss 从 150 秒提前到 60 秒登场。
2. **抽卡里程碑化**：一局固定 3 次，落在三段杂兵的交界，不再由能量随机触发。
3. **局外晋升**：通关一次档位 +1，敌人变强、星尘变多，给"再来一局"一个具体理由。

---

## 1. 现状（实测数据）

| 项 | 现状 |
| --- | --- |
| 单局参考时长 | `RUN.duration = 180` 秒 |
| Boss 登场 | `RUN.bossAt = 150` 秒 |
| 杂兵编排 | 8 段连续波次，0–150 秒无缝铺满，中间无高潮 |
| 抽卡触发 | 能量满即弹，阈值 `140 × 1.18^level`，每杀 10 点 |
| 实际频率 | 150 秒约 8 次，平均 18–20 秒一次 |
| Boss 血量 | `2800 × (1 + 0.22 × 选卡数)` |
| 局外 | 4 项永久强化（约 10 级）、最高分、星尘、局数 |
| 局内难度曲线 | `difficulty()` 按本局时间从 1.0 线性拉到 1.8，作用于敌机血量与开火间隔（`RUN.duration` / `rampFrom` / `rampTo` 都参与其中） |

### 为什么"一次性"

不是局太长，是**一局结束后没有下一局的承诺**：

- 敌人编排、Boss、关卡长度每局完全相同
- 局外 4 项强化点满后，星尘失去用途
- 结算页只有分数，没有"我变强了 / 下一档更难"

---

## 2. 目标与非目标

### 目标

1. 从开局到 Boss 登场 **≤ 62 秒**，完整通关 **90–110 秒**。
2. Boss 前**恰好 3 次**三选一，且落在可预期的位置。
3. 两局之间 build 不同；通关后下一局可感知变难，收益同步变高。
4. 失败局在 30–60 秒内结束，不惩罚重开。

### 非目标（本轮不做）

- 每日种子挑战、排行榜接入
- 机体解锁阶梯、新 Boss、新敌机
- 关卡地图 / 分支推图（与短局循环冲突）

## 3. 单局时间轴

| 时间 | 内容 | 设计意图 |
| --- | --- | --- |
| 0–20s | W1：无人机，间隔 1.3s、单架 | 热身，先让玩家站稳 |
| 20s | **抽卡 ①** | 第一次变强 |
| 20–38s | W2：无人机横排 + 炮台 | 弹幕开始出现 |
| 38s | **抽卡 ②** | 拿到应对手段 |
| 38–58s | W3：编织机两翼 + 无人机横排 + 结尾炮台 | 密度峰值 |
| 58s | **抽卡 ③** | 决战前最后一次补强 |
| 60s | Boss WARNING（停帧 + 运镜 + 预警音） | 高潮起点 |
| 62–100s | Boss 三阶段 | 收尾 |
| 结束 | 结算：星尘 / build / 档位晋升 | 制造"再来一局" |

### 波次表

```ts
export const RUN = {
  duration: 100,
  bossAt: 60,
  cardAt: [20, 38, 58] as const,
  rampFrom: 1.0,
  rampTo: 1.35, // 局内爬升终点（原为 1.8）
  rampEnd: 58, // 爬到 58 秒封顶，Boss 战不再加码
};

export const WAVES = [
  { at: 0,  until: 20, kind: "drone",  interval: 1.3, count: 1, pattern: "random" },
  { at: 20, until: 38, kind: "drone",  interval: 1.0, count: 2, pattern: "line" },
  { at: 24, until: 38, kind: "gunner", interval: 3.4, count: 1, pattern: "random" },
  { at: 38, until: 58, kind: "weaver", interval: 1.2, count: 2, pattern: "sides" },
  { at: 40, until: 58, kind: "drone",  interval: 1.4, count: 2, pattern: "line" },
  { at: 52, until: 58, kind: "gunner", interval: 4.0, count: 1, pattern: "random" },
] as const;
```

预估生成约 115 架，压缩在 58 秒内。

> **调参记录（2026-10-20）**：初版第三波用 0.9 / 1.1 / 50s，自动驾驶 8 局里有 2 局在 46 秒被击落、根本见不到 Boss。
> 削到 1.2 / 1.4 / 52s 后，8 局 7 胜 1 负，死亡点推到 53.7 秒。这条是实机分布，不是拍脑袋。

## 4. 抽卡：里程碑制

### 规则

- 触发条件改为 `world.time >= RUN.cardAt[i]`，与击杀量无关。
- 每次触发只发一次：先推进里程碑下标，再打开三选一，避免恢复后重复弹。
- Boss 前固定 3 次；Boss 战期间不发牌。
- 卡池仍是 11 张、每张三选一，炫彩卡每局一次。

### 能量条的去向

- `gainEnergy` 不再触发抽卡。
- HUD 的 `energyPct` 改为**到下一张卡的进度**（按时间推进），语义仍是"快升级了"。
- HUD 以 10Hz 推送，保证进度条平滑；DOM 写入量可以忽略。
- **局外"能量引擎"随之失效**（它原本只加能量获取速度），改成"装填加速：射击间隔 -6%/级"，存档键仍是 `energy`，不破坏旧档。

### 为什么不用"只调能量曲线"

能量触发依赖击杀数：打得越顺，抽卡越密，密集波里可能连弹两张，打断操作。里程碑制把节奏从"表现驱动"改成"关卡驱动"，玩家能预期下一次变强。

## 5. Boss 重算

抽卡从约 8 次降到 3 次，Boss 血量公式里的等级项会大幅缩水，必须同步调整：

| 参数 | 现值 | 新值 |
| --- | --- | --- |
| `BOSS.hp` | 2800 | **3200** |
| `BOSS.hpPerLevel` | 0.22 | **0.18** |

3 卡时血量约 `3200 × 1.54 ≈ 4928`，目标是**战斗落在 20–35 秒**。

> 实测（自动驾驶 8 局，取胜利的 7 局）：Boss 战 11–46 秒，整局 71–106 秒。
> 方差主要来自抽到的卡（自动驾驶固定选第一张），人类玩家按 build 选牌会更稳定。

## 6. 难度档位（rank）

`rank` = 已通关次数，从 0 开始；胜利时 +1。

```ts
export const RANK = {
  enemyHp: 0.08,     // 每档敌人血量 +8%
  spawnRate: 0.03,   // 每档出怪间隔 -3%
  bulletSpeed: 0.02, // 每档敌弹速度 +2%
  bossHp: 0.10,      // 每档 Boss 血量 +10%
  stardust: 0.15,    // 每档星尘收益 +15%
  spawnMin: 0.70,    // 出怪间隔不低于原值 70%
  bulletMax: 1.20,   // 敌弹速度不超过原值 120%
} as const;
```

约束：

- 出怪间隔乘 `max(spawnMin, 1 - spawnRate × rank)`
- 敌弹速度乘 `min(bulletMax, 1 + bulletSpeed × rank)`
- 敌人血量乘 `1 + enemyHp × rank`
- Boss 血量乘 `1 + bossHp × rank`（与选卡系数相乘）
- 星尘乘 `1 + stardust × rank`

档位不设上限，但出怪与弹速有硬上限，避免高档位变成不可玩。

### 与局内难度曲线的关系

原有 `difficulty()` 表示"同一局内越打越难"，`rank` 表示"跨局越来越难"，两者作用在不同维度：

- 局内曲线保留，但终点从 `1.8` 收到 `1.35`，止点从 180 秒收到 58 秒——单局变短后，原来的爬升幅度会在杂兵段末就过于陡峭
- `rank` 在局内曲线之外再做乘算（敌血、出怪间隔、弹速、Boss 血、星尘）
- 这样第 0 档的新手和高档玩家的压力差异来自档位，同一局内部的爬升仍然可感知

## 7. 存档与结算

### 存档

`MetaData` 增加 `rank: number`；旧存档缺字段时按 0 补齐，不破坏现有玩家数据。

### 结算

- 胜利：`rank +1`，展示"第 N 档 → 第 N+1 档"和本局拿到的卡
- 失败：档位不变，展示星尘与最高分
- 主菜单入口显示"再来一局 · 第 N 档"

## 9. 测试与验收

### 单测

1. `WAVES` 在 0–58 秒内连续覆盖，无空档；58–60 秒是决战前留白。
2. `cardAt` 严格递增，且最后一个小于 `bossAt`。
3. 档位缩放单调递增，且出怪/弹速在上下限处夹紧。
4. `loadMeta` 对缺少 `rank` 的旧存档补 0。

### 实机

- `?auto=1` 跑完整局：Boss 在 60 秒登场，通关落在 70–110 秒。
- Boss 前恰好弹 3 次卡，恢复后不重复弹。
- 连续两局 build 不完全相同。
- 胜利后档位 +1，下一局敌人变强、星尘变多。
- `tsc --noEmit`、`eslint`、全部单测通过。

---

## 10. 风险

1. **3 张卡打 3 阶段 Boss 可能太薄**：若实测战斗短于 20 秒，上调 `BOSS.hp`；若长于 40 秒，下调。
2. **里程碑抽卡与击杀脱钩**：打得快不再更快变强。作为补偿，武器等级仍按 `level % 3` 自动提升。
3. **档位过高导致数值失真**：出怪与弹速已有硬上限，剩余压力交给血量和 Boss。
